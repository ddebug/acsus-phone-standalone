# 独立小手机 · Acsus Phone

从 [Acsus-Paws-Puffs](https://github.com/Hmkovo/Acsus-Paws-Puffs) 2.0.0 的小手机模块独立出的 **SillyTavern / TauriTavern 前端扩展**。不是单独运行的聊天网站，也不包含酒馆后端。保留原来的联系人、聊天、表情、收藏、手机 API/预设、约定计划、模拟钱包/会员及装扮等模块；未实现的原版占位功能仍是占位。

**当前仍是验证版，不代表全部宿主版本、模型供应商和手机设备已实测。** 原版权与授权见 [AUTHORS.md](AUTHORS.md) 和 [LICENSE](LICENSE)，不能擅自作为开放许可代码再分发。

## 安装

1. 在原 Acsus-Paws-Puffs 中关闭“手机”功能，然后刷新或重启酒馆。只关闭窗口不算关闭功能；原扩展的其他功能可以保留。
2. 将本仓库文件放进一个独立扩展文件夹 `acsus-phone-standalone`，文件夹根下必须直接有 `manifest.json`，不要多套一层。
   - SillyTavern 通常位于 `data/<用户>/extensions/acsus-phone-standalone/`。
   - TauriTavern 通常位于应用数据目录下 `data/<用户>/extensions/acsus-phone-standalone/`。
3. 刷新或重启宿主，在扩展设置中找到“独立小手机 · Acsus Phone”，也可从扩展菜单打开手机。

本仓库为私有仓库时，酒馆的“按 URL 安装”不一定能认证 GitHub。可在已登录账号下下载 ZIP 并解压，或使用已经具有仓库访问权限的 Git 客户端。不要把 GitHub token 填入插件代码。当前关闭自动更新，避免暗示私有仓库更新已配置。

**不要同时运行原版与独立版小手机。** 独立版隔离了存储、草稿、菜单与宏，但仍沿用大量手机 UI 的 DOM/CSS；原版残留 CSS 也可能影响展示。入口会检查原版菜单并观察后续插入，发现冲突时停止独立版；这是尽力检测，不是完整的插件互斥锁。出现冲突时关闭原版手机后刷新。

## 聊天与设置存在哪里？

手机自己的聊天、联系人、收藏和配置通过宿主用户文件 API 保存为：

```text
<酒馆用户数据目录>/user/files/acsus-phone-standalone.json
```

浏览器路径为 `/user/files/acsus-phone-standalone.json`。这不是插件源码文件，不应提交到 Git。独立版的 `extension_settings` 只是自己的内存 facade，**不把手机数据写回酒馆总配置，也不自动读取原插件设置**。实际用户隔离、请求认证和磁盘写入由宿主负责，兼容性取决于宿主是否提供这些标准文件接口。

- 只有确切的 404 表示首次使用。读取失败、文件损坏、格式版本不兼容时停止启动，不用默认空数据覆盖。
- 保存为串行操作，并在写入前检查版本、写入后读回确认。保存失败／结果不明确会显著提示；先导出内存备份，不要强制刷新或覆盖。
- 宿主文件 API 没有原子条件写入（CAS）。版本检查和同浏览器锁仅降低冲突，**不能保证跨设备／跨浏览器并发安全**。同一份手机数据一次只在一个页面编辑；换设备前确认已保存，另一设备重新载入。
- 切后台时尝试保存；关闭页面的提醒也是尽力行为，不是断电保护。看到“正在保存”或“有未保存的数据”不要立即结束应用。
- **宿主“清理未使用文件”的功能可能把这个独立文件当作未使用文件删除。清理之前必须手动导出备份，排除该文件；本插件不会修改宿主清理规则。**
- 自定义 API 凭据如果由用户填写，仍属于敏感手机配置；独立文件不是加密保险箱。不要公开手机数据文件或备份。

存储接口依据 [SillyTavern files API 源码](https://github.com/SillyTavern/SillyTavern/blob/release/src/endpoints/files.js) 与 [用户文件路由](https://github.com/SillyTavern/SillyTavern/blob/release/src/users.js) 实现；这不代表每个 TauriTavern 版本都已运行验证。

## 旧聊天手动导入与备份

扩展设置区提供导出、导入、保存状态和刷新入口。

- 默认导出移除 API key、认证头、token、密码等凭据字段。勾选“包含 API 凭据”才导出完整敏感配置。**即使不含密钥，备份仍包含私人聊天。**
- 手动选择本插件备份、原版 `phone` 数据对象，或用户自己选出的完整酒馆设置 JSON。只从该文件提取手机部分，不读取本机其他设置；从完整旧设置导入时也处理顶层 `extension_settings.phone.favorites` 的旧收藏。
- 默认导入不迁移 API 凭据。确认导入会覆盖独立版的全部手机数据；原插件原记录不删除、不修改。
- 覆盖之前在相同用户文件目录保存独立的 `acsus-phone-standalone-before-import-…json` 备份并读回核对，失败则不覆盖。导入成功后必须刷新，避免旧页面持有过时对象。
- 备份只记录图片／表情文件路径，不会打包实际图片。原设备仍需保留那些媒体；本插件删除图片／表情时只移除自己的记录，不物理删除宿主共享文件，因而不会通过导入引用误删原版图片。
- 不要导入不可信备份。旧版 UI 大量使用 HTML 模板，独立化不是对整个上游实现的全面安全审计。

## 界面主题

点击手机顶部头像 → 个人主页底部「手机界面主题」下拉选择：**日间 / 经典夜间 / 深夜毛玻璃**。原有两个主题保留，升级不会自动改成新主题；选择保存到手机独立数据中。

- 深夜毛玻璃使用石墨蓝灰底、低饱和强调色、半透明顶栏/底栏和弹窗、柔和细边框与圆角；不加载外部字体或背景图片。
- 同时修复三种主题的输入/编辑框、选择框、占位字、光标和聚焦边框的配色；补齐日记卡片/边框的颜色变量。经典夜间保留原配色，只做可读性修复。
- 手机自带弹窗、调试面板和消息通知继承手机主题；通知在手机关闭后到达也会使用已保存主题。不向宿主 body 写入界面主题，帧内同步观察器随手机关闭清理。
- 用户装扮气泡和自选聊天背景仍保留优先级。移动端保持全屏尺寸；不支持毛玻璃或系统要求减少透明度时退回实色面板。
- 本次只做静态 JS/导入检查与 CSS 解析、源码复核，未在真实宿主完成视觉/触控验收。

## 从 LLM 日志补录未保存的角色回复

**0.5.3 起统一到聊天底栏机器人图标 → 调用调试 → 补录角色回复页签**；聊天设置中的“调用调试 / 补录回复”只是同一窗口的快捷入口，不再另开补录页面。没有缓存返回也能打开补录，无需先调用模型；有返回时可直接使用当前调试框内容，不同草稿会先确认替换。原“调用调试”页签保留版本、对比、检查、重新应用及重 roll；**重 roll 会请求模型，补录不会**。补录保存成功或写入结果不明后，旧回退快照都会停用（重开窗口也不能绕过），以免再删除人工补进来的消息。没有真实发送前快照时，不开放回退或重 roll。

只粘贴日志里该角色的**最终回复文字**（或单角色 `[角色-名字][消息]…[/消息]` 格式），选择原消息的本地时间，先预览再确认保存。一次补录为一个普通文字气泡；会按时间插入，像正常聊天一样进入后续上下文。不会重发模型请求，不执行转账、计划、好友等操作，也不触发来信通知。

- 不粘贴整份 API 请求/响应 JSON、SSE、密钥或推理日志；这不是 API 原包导入器。已识别的 `<think>` 和 `<phone-extras>` 包裹会从聊天预览中剥离，小剧场**不会由此入口补录**。无法可靠识别的操作/日志结构会拒绝，让用户只复制最终正文。
- 默认勾选“主动唤醒回复”。新增的今天主动补录会保守计入今天一条消息额度，不占模型尝试次数；没有更晚真人发言时建立等待标记，避免连续主动发送。历史日期不占今天额度，有后续真人发言则不重复建立等待；若是普通回复可取消勾选。保存会先暂停并等本页面的在途主动任务结束，不把其他角色卡在未完成预留状态。
- 相同正文会警告，正文与时间都已存在时只查看、不再新增；同文异时需明确勾选是另一条回复。不可变预览、稳定消息 ID 和串行保存防止双击重复。补录不清空其他待操作内容。
- 只有独立手机文件写入并读回确认后才报告成功，再补显缓存聊天；旧日期内容可能要上滑。保存失败/结果不明会保留内存内容供备份、锁住继续补录，**先导出手机备份再刷新，不要重复点击补写**，避免服务器其实已写入却产生第二条。
- 本轮只做源码/语法/内部导入静态复核，没有调用模型、读取私人日志或执行运行测试；不会凭空找回服务器已丢弃且用户没有提供的旧回复。

## 角色小剧场（独立附加内容）

聊天右上角设置 → **角色小剧场**。默认关闭，开关与写作提示词全手机共用。可以自定义“心理活动”“小彩蛋”“想做却没做的事”等栏目；仅为虚构角色描写，不是模型内部推理。

- 开启后，在小手机的一次聊天生成请求中，模型先正常回复，再附带一个独立包裹；不会为了小剧场再调用一次模型。会增加当次提示词/输出 token，但已有小剧场**不累积进后续上下文**。提示词修改只影响之后发起的生成，关闭保留旧记录。
- 普通模式包裹协议固定为 `<phone-extras>{"role":"角色名","sections":[{"title":"心理活动","content":"内容"},{"title":"小彩蛋","content":"内容"}]}</phone-extras>`；写作提示词可改，外层协议不可改。工具模式在同一响应中使用 `phone_record_extras`，只在该角色有实际保存的普通消息时记录；主动消息的 `[不发]` 不记录小剧场。
- 包裹在普通回复格式校验、调试快照、消息解析之前剥离；无效/未闭合尾包裹直接隐藏，不混进聊天。生成内容用纯文本显示，不执行 HTML。模型漏写或格式无效时跳过附加内容，不补发请求；已经成功保存的正常消息保留。
- 独立保存到 `phone.characterExtras[contactId].entries`，不放在聊天正文、消息 metadata、待发队列、日记源记录或正文宏中。完整手机备份包含这些条目；UI 可折叠查看和单独删除，删除不会改聊天。每角色最多 1000 条，满后拒绝新条目，不偷偷清理旧条目。重 roll 新回复可新增条目，旧小剧场不会跟着聊天自动删除。
- 页面显示条目生成时间，默认保留两节；可用自己的提示词指定 1–6 节。存储写入失败/不明确不自动重试或强制覆盖。本轮仅做源码/语法/导入静态检查，未调用真实模型或运行测试。

## 空白纸飞机：手动主动继续

0.5.4 起，聊天输入框为空、当前联系人没有待发送消息，也没有尚未回复的用户消息时，点击纸飞机会**手动邀请该角色主动继续**。不需要开启后台主动设置、勾选角色或等待2小时/固定时刻；这是用户主动操作，可在免打扰时段使用。每次点击会调用当前手机模型 API，可能产生正常模型费用；不会替用户打开后台定时功能。

- 隐藏提示复用主动链路的当前时间/沉默时长，并说明用户此刻手动邀请继续；不制造空白或伪造的用户气泡，隐藏提示也不写入聊天、日记或未来上下文。
- 已暂存的文字/图片/表情、当前未回答的用户消息仍走原普通发送；不因输入框刚清空就忽略用户，也不由手动空轮消费其他联系人的待发队列。尚未暂存的草稿仍沿用原两按钮操作，不在此功能中自动提交。
- 返回只接受一个普通文字气泡（不执行转账/好友等操作）；模型返回 `[不发]` 只显示提示，不增加消息。启用小剧场时仍同次请求分开保存。输入框不在场时的通知尊重联系人隐私设置；当前聊天可见时不额外弹自己的通知。
- 手动请求不受后台自动次数/条数上限、等待真人回复条件拦截，也不占自动配额；成功后会设置等待标记，避免后台立即再主动发。下一次用户明确点空白纸飞机仍可继续。普通后台检查的免打扰、15分钟、配额与开关规则完全不变。
- 准备锁与同步前台所有权避免双击发两次；生成时纸飞机变停止，取消不自动重试。等待在途后台任务收尾后才使用共享存储。仅严格确认消息文件后才显示，保存未确认先备份再刷新，不二次补写；已校验的可见返回保留在调用调试中，不保存隐藏提示或小剧场原包，也不伪造可回退的普通快照。
- 仅经源码/语法/导入静态检查，未发送真实模型请求或执行运行测试。

## 角色主动消息

手机头像 → 设置 → **角色主动消息**。默认关闭；先勾选允许角色，再启用并保存。启用后会自动调用手机当前使用的模型连接，可能产生 API 费用。

- 每 15 分钟检查：同一角色的用户沉默默认 2 小时（可改），**或者**到达填写的每日固定时刻（如 `22:30`）。按设备本地日期/时间判断，固定时刻在下一次检查处理，不保证整分；仅处理同日最近 15 分钟到期的时刻，不补发整夜积压。
- 使用正常聊天预设、目标角色资料及已配置的历史窗口（包含有效日记替换）；只在本次后台请求末尾追加隐藏系统提醒：`[系统：现在是{{当前时间}}，user已经{{间隔时长}}没说话了。你可以主动给她发消息，也可以不发。如果不想发，只回复[不发]。]`。它不进入待发送队列、调试快照或聊天记录；不会消耗/清空用户的待发消息。
- 模型只返回 `[不发]` 时静默跳过；否则本功能每次只接收 **一个普通文字气泡**，照常写入聊天记录并更新消息列表、通知（尊重联系人关闭通知/隐藏预览设置）。不会自动执行转账、好友申请、个签等操作。
- 本地 **01:00–09:00** 不主动请求/通知；用户手动发消息和正常请求不受限制。发出一次主动消息后，同一角色需要收到新的用户消息才可再次主动；回复别的角色不解除等待。
- 所选角色合计默认每天最多 **5 条实际主动消息**，可设 1–50。为避免模型不断选择不发而无限付费，另限制每日自动模型尝试 `max(20, 消息上限 × 4)` 次；不发、失败和取消也占尝试预算。
- 请求前先持久化预留，消息与额度确认写入后才通知。**只有已发送、请求中断状态不明或写入未确认才保留等待标记**；明确在保存前失败/取消/被校验丢弃且没有对应聊天消息的尝试，不再永久误锁为“等用户回复”，以后仍按15分钟检查、固定时刻和每日尝试预算判断。旧版这类已明确未发送的失败也会恢复资格；不会立即循环重试。结果不明或写入冲突仍先备份，不自动强制覆盖或重发。
- 0.5.1 修复首次自动请求补默认 API 配置后自我触发“上下文改变”、把成功回复丢弃的路径；主动请求沿用手机 API 的输出额度，不再另压到1024 token。消息的严格保存已确认后，不因后续未读数写入失败而阻止显示。缓存聊天补显失败时，点击通知会重新读取已保存消息补显（不调用模型，不复活已删除记录）。
- 本页「运行状态」现区分等待写入、已确认保存、保存未确认，并显示已知的校验/取消/超时/格式/存储原因；不输出提示词、回复正文或 API 密钥。用户手动发消息、前台普通生成、设置变更和禁用插件仍会取消在途后台检查。修复仅经静态源码/语法/导入复核，未发送真实模型请求或执行测试，不能凭源码断言某次用户日志命中了哪条路径。
- 必须保持酒馆页面在线；关闭小手机窗口仍可运行，但关闭应用、页面休眠/系统挂起不会成为离线后台服务。需要支持 **Web Locks** 的客户端/localhost/HTTPS；缺少安全互斥时停止自动付费请求并提示。只在 **一个浏览器/设备**运行；文件预检不是跨设备的原子锁。
- 当前仅源码/语法/导入静态复核，未实际运行定时或付费模型验收。

## 聊天日记（压缩历史上下文）

聊天设置 → **聊天日记**。它把每天的聊天记录交给 AI 写成一篇日记，之后发送上下文时，已经写过日记的日期会被这段日记替换，原始消息不再逐条发送。

- 展开「总结提示词（点击编辑）」可修改和保存总结写法、篇幅及引用要求，也可恢复默认。默认角色第一人称、按时间顺序、标大概几点，**不强制保留原话**。提示词全手机共用，随数据备份；只影响之后的生成，不自动改写旧日记。未保存的编辑会在生成前询问是否保存，取消则不请求；插件仅额外固定按日期返回 JSON 的存储协议。
- 日期列表可点「总结当天」，也可勾选一个或多个日期后「总结勾选日期」。已总结的日期也可重选，覆盖旧日记前会确认。保留「一键总结全部待总结」和「全部重写」；每次操作至多一次模型生成请求。
- 每个日期后显示当天未排除原始聊天文本的 **token 估算**（含日期/时间/说话人，复用生成请求的同一格式）。优先使用[宿主当前 tokenizer](https://github.com/SillyTavern/SillyTavern/blob/release/public/scripts/tokenizers.js)，不可用时按 UTF-8 字节量粗估并标注；计数调用分词接口，不调用模型生成。它不包含角色资料、总结提示词、请求包装或图片视觉 token，不代表请求总量或供应商实际计费。
- 即使只选择一天，背景仍携带全部原始历史；减少所选天数主要减少日记输出，不会按所选天数裁剪输入背景。
- 生成后，日期行和已有日记标题分别显示「原文 token / 总结正文 token」估算；旧日记也会自动补算。总结按保存的正文统计，不包含日期标签、请求包装，重写后按新正文重新计算；计数失败单独显示，不影响总结的保存。
- 每篇日记可勾选「本日上下文使用原文（保留总结）」，只停用这一天的日记替换，不删除正文或原消息；取消勾选可恢复使用有效日记。重写同一天的总结也保留此选择，设置随手机数据保存。全局开关关闭、最近聊天日期或日记已过期时仍会用原文。
- 每篇已有日记展开后可点「编辑正文」手动改写：只写回正文，**不改原始聊天、不改变这一天的「使用原文」选择，也不调用模型**；保存后立即用于替换该日上下文，并按新正文重算「总结 token」。正文不能保存为空。保存时沿用原有源记录指纹，所以这一天仍算已总结；原记录之后再增删改，仍会重新标为待总结。
- 未保存的正文修改按日期留在内存草稿里：切换「使用原文」、刷新列表、切换联系人再回来都不会丢，重绘后该篇会自动展开并保持编辑态；只有重新加载手机/宿主才会清空。取消编辑会丢弃草稿并保留原正文。例外：这一天的日记被重新生成（「重写当天」「全部重写」等）后，该天残留的草稿会清掉，以新生成的正文为准；删除这一天的日记时草稿也一并清理。
- 原文/日记切换只改变原有发送范围内的历史替换方式，**不会绕过最新/历史条数设置强制发送某天全部记录**。可展开「查看当天原文」核对这一天的原始记录（已排除项仅在本地标注预览，不计 token 或参与发送），查看不会发起生成请求。删除总结才会真正删除日记条目；不必为临时发原文而删除总结。
- 每天 **20 条及以下不总结**；页面逐日列出「待总结 / 已总结 / 条数太少跳过」及消息条数。原记录增删改后，对应日记会重新标为待总结，不再替换已变动的原文。
- 「一键总结全部待总结」「全部重写」均只发送 **一次 API 请求**，一次返回全部目标日期，再按日期分别保存。单日重写也只发一次请求；没有符合条件的日期时不请求，不自动拆天重试。
- 每次生成都带上该联系人**全部未排除的原始手机历史**（包括已总结日及 ≤20 条的背景日期），不受最新/历史条数设置限制，不用旧日记替代来源；同时带上该角色卡、人设、用户设定和普通聊天已启用的角色资料条目（世界书/自定义/线下剧情等），供模型识别自己是谁。
- 全历史过长仍受供应商上下文和输出上限限制。插件不静默裁剪、不自动追加模型请求；返回被截断、日期缺失或重复时，本轮不覆盖旧日记。生成过程中若聊天/日记变化，也停止保存，避免把旧结果覆盖新记录。
- 最近一天还在继续聊，会保留原始记录，不会被日记替换，避免和最新消息重复。
- 日记生成走酒馆当前默认连接（等同于正常聊天），不会另存 API 密钥；日记和手机其他数据一起保存在独立用户文件里。
- 升级前的日记缺少源记录指纹，会保留在列表中，但重新列为待总结，整理一次后才再次替换原文；避免把无法核对的旧摘要当成最新内容。
- 日记是模型写的摘要，可能漏细节；引用原文时以聊天记录为准。
- 手动编辑仅经源码/语法/导入静态检查，未在真实宿主做触控、主题与长文编辑的视觉验收；保存复用日记生成同一条手机数据写入路径（写入失败回滚并提示，不静默丢弃改稿）。

## 宿主与网络边界

运行时依赖宿主模块、Font Awesome、jQuery/排序组件和通知接口。默认 API 使用酒馆当前连接；自定义 API 与模型刷新也通过宿主后端，不额外部署服务器。

角色卡、世界书、预设和正则同步，以及线下剧情上下文，可按原手机功能读取宿主资料／聊天。独立存储不等于禁止所有宿主上下文访问。天气宏会请求 `wttr.in`；用户填写的外链图片会访问对应图片站。默认外链占位图已替换成内联 SVG。没有添加遥测或自动上传聊天到 GitHub 的功能。

为避免与原手机版本的宏冲突，独立版使用：

```text
{{standalonePhoneRecent}}
{{standalonePhoneRecent::角色名}}
{{standalonePhoneHistory}}
{{standalonePhoneTime}}
{{standalonePhoneWeather}}
```

旧提示词中的 `phoneRecent` 等名称需要手动更换，旧插件自己的宏不由本插件接管。

正文宏与手机 API 现共用历史选择/紧凑格式：先按原始消息条数切 recent/history 窗口，再在 history 窗内用源记录仍有效、未选择“使用原文”的日记替换；最新聊天日和 recent 保持原文，不扩大历史窗口。首条/跨日显示日期和时间；用户每条独立，同次 API 的连续角色消息只显示一组时间/说话人，不输出楼层号，引用不重复整段原文。新回复保存明确 `apiCallId`；旧记录缺调用 ID 时仅能采用 30 秒兼容推断。图片、签名等仍保留各 API 必需的结构化边界，纯文本宏不包含实际图片附件。宏仍需放在你希望注入的预设/世界书位置，不会自动新增正文楼层，也不自动把酒馆主聊天回复收集为小剧场。

## 开发与验证

无需构建即可安装运行。测试使用 Node 20+ 的内建测试框架，不需要 npm 安装运行时依赖：

```sh
npm run check
npm test
```

`check` 检查模块语法、内部静态/动态导入、宿主模块白名单、旧存储/保存入口残留、共享媒体物理删除、许可证哈希和常见凭据模式；模式检查不等于完整安全审计。测试仅用合成数据和宿主替身，不访问真实用户设置、不调用付费 AI。

`npm run test:browser` 启动仅绑定 `127.0.0.1` 的合成宿主 fixture，打印确切地址。它不会启动真实酒馆，不读实际用户数据，模拟文件仅在进程内存；关闭进程后测试数据消失。真实宿主兼容性、付费模型生成、触控和全部历史数据迁移仍需另外验收。

验证记录见 [docs/VERIFICATION.md](docs/VERIFICATION.md)。原始代码输入摘要见 [docs/upstream-snapshot.json](docs/upstream-snapshot.json)。
